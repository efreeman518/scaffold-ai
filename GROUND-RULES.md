# Ground Rules

Binding across `/scaffold`, `/vertical-slice`, and `/scaffold-adopt`. Stable `GR-NN` IDs let gates, skills, and templates cite these canonical short forms; linked owners contain enforcement detail.

Conflict order is domain-scoped, not a single ranking: routing, loading, and session-boundary conflicts follow [START-AI.md](START-AI.md); validation command and gate conflicts follow [support/execution-gates.md](support/execution-gates.md); implementation conflicts follow [ai/SKILL.md](ai/SKILL.md) > skills > templates. Canonical statement: [`ai/SKILL.md`](ai/SKILL.md) section Non-Negotiables - this index does not restate or override it. For a conflict outside those three domains, the file that owns the topic per **GR-12** wins.

## Rules

| ID | Rule | Why | Enforcement |
|---|---|---|---|
| **GR-01** | Phase 1 artifacts (`domain-specification.yaml`, `UBIQUITOUS-LANGUAGE.md`, `DESIGN-DECISIONS.md` under `.scaffold/`) are binding. Update the artifact before code. On discovered drift, code reality wins; correct the artifact, then the code rather than divergence-patching silently. | Later phases and slices reason from these files; stale artifacts make sessions invent or contradict the domain. | [START-AI.md](START-AI.md), Phase-1 Artifact Lifecycle Rule; [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; [support/HANDOFF.md](support/HANDOFF.md), Phase-1 Artifact Currency; advisory `scripts/check-artifact-drift.py`; `scripts/generate-ontology.py --check` when `.scaffold/ontology/` exists. |
| **GR-02** | Generated code, including `src/Packages/<packagePrefix>.*`, has one public type per same-named file. Split files that lump unrelated types; a cohesive family read and changed together is exempt per the owner's list. | Lumping unrelated types obscures coupling and impairs navigation and refactoring; later splits cost more. Splitting a cohesive family costs more than it saves. | [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; exceptions in [skills/solution-structure.md](skills/solution-structure.md), Non-Negotiables; acceptance in [support/final-scaffold-checklist.md](support/final-scaffold-checklist.md). |
| **GR-03** | Use `.slnx` and `Directory.Packages.props`; do not generate `.sln` or per-project `<Version=>` references. | Per-project versions drift, causing inconsistent restores and behavior; one project graph and version table remove competing update points. | [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; [skills/package-dependencies.md](skills/package-dependencies.md). |
| **GR-04** | Minimize third-party packages. Use only the reference-app and conditional React allowlists in `ai/SKILL.md`; any addition needs developer confirmation, high-value justification, and a `.scaffold/DESIGN-DECISIONS.md` entry. Paid-license packages and tools are excluded unless they add significant value and no free option exists. | Each dependency adds transitive code, licenses, advisories, and upgrade coupling; requiring a capability gap limits permanent maintenance surface. A paid license adds recurring cost and a vendor dependency to every scaffolded app. | [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; [skills/package-dependencies.md](skills/package-dependencies.md), Minimize Third-Party Dependencies. |
| **GR-05** | Before Phase 5 generates integration code, record each external dependency under `externalDependencyModes` in `.scaffold/resource-implementation.yaml` as `emulator`, `lazy-optional`, `no-op stub`, or `deployment-only`. | An unspecified mode either blocks on cloud setup or throws at runtime; an explicit mode keeps local boot deterministic. | [ai/SKILL.md](ai/SKILL.md), Key Principles; [support/execution-gates.md](support/execution-gates.md), Aspire AppHost. |
| **GR-06** | Stub external dependencies for local compile/run. Even `deployment-only` needs an interface-complete no-op, safe defaults, and `// TODO: [CONFIGURE]`. Live cloud provisioning never blocks scaffold completion. | Scaffold completion proves local compile, run, and end-to-end tests; production configuration is a delivery concern. | [ai/SKILL.md](ai/SKILL.md), Key Principles; [templates/no-op-stub-template.md](templates/no-op-stub-template.md); [support/final-scaffold-checklist.md](support/final-scaffold-checklist.md). |
| **GR-07** | Generate code only in the target project. Never edit installed `.instructions/` during scaffolding; record gaps in root `.scaffold/INSTRUCTION-GAPS.md`. | One source instruction set serves many projects; target edits create silent drift, while the gap log preserves findings for source maintenance. | [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; maintainer skill `/fold-feedback`. |
| **GR-08** | Default SDKs, runtimes, packages, and actions to latest stable. Instructions use placeholders, generation resolves reproducible project refs, and no baseline prose hard-codes versions. A temporary exception records the issue, reason, removal condition, and validating test. | Version-specific prose goes stale and contradicts the moving baseline; documenting only the current API avoids release-by-release repair. | [skills/package-dependencies.md](skills/package-dependencies.md), Latest, Not Pinned; [skills/cicd.md](skills/cicd.md), Action References. |
| **GR-09** | Run each phase in its own session and each Phase 5 sub-phase in its own session. End with updated root `HANDOFF.md`; resume from only `START-AI.md` and `HANDOFF.md`. | Session boundaries cap context, preserve load-set limits, and create review points. | [START-AI.md](START-AI.md), Session Model and File Loading Rule; [support/HANDOFF.md](support/HANDOFF.md). |
| **GR-10** | Put `[OPEN QUESTION: <single-sentence question>]` in the relevant Phase 1/adoption `.scaffold/` artifact and mirror it in `HANDOFF.md` Open Questions. A blocking marker halts the next phase until resolved or deferred with `Needed Before`. | Literal markers make ambiguity scanable and durable instead of leaving it in session memory. | [ai/shared-understanding-interview.md](ai/shared-understanding-interview.md), Clarification Quality Rules; [ai/implementation-plan.md](ai/implementation-plan.md), Open Questions; [support/operator-setup.md](support/operator-setup.md), Tooling Verification; [support/HANDOFF.md](support/HANDOFF.md), Open Questions. |
| **GR-11** | Definition of Done is broader than a green build: runtime composition, host startup, quiet logs, gated-test honesty, and Phase 1 artifact currency all count. The criteria list is owned by the checklist named in the owner column - walk it, do not restate it. | Build-only checks miss runtime composition, host drift, noisy startup, and gated-test gaps, allowing an unusable scaffold to appear complete. | [support/final-scaffold-checklist.md](support/final-scaffold-checklist.md) owns criteria; [support/HANDOFF.md](support/HANDOFF.md), Scaffold Acceptance records evidence. |
| **GR-12** | Authority: [START-AI.md](START-AI.md) owns session boot, phase routing, and load rules; [support/execution-gates.md](support/execution-gates.md) owns validation gates/commands; [ai/SKILL.md](ai/SKILL.md) owns Phase 5 load sets/routing; skills own implementation detail; templates own generated shape. This file only indexes binding rules. | Single ownership prevents conflicting copies of the same decision. | `START-AI.md`, Conflict Resolution Order; `ai/SKILL.md`, Non-Negotiables. |
| **GR-13** | Migration policy is flow-scoped. Greenfield `/scaffold` has no compatibility obligation and resets each schema change to one `InitialCreate` (`dotnet ef migrations remove --force`, then re-add). `/scaffold-adopt` and `/vertical-slice` preserve history with `dotnet ef migrations add <Change>`; never drop/recreate. | Resetting is clean only before lineage matters; in established apps it destroys migration and applied-schema history. | [support/execution-gates.md](support/execution-gates.md), 5a - Foundation; [patterns/data-layer-wiring.md](patterns/data-layer-wiring.md), Scaffold Migration Strategy. |
| **GR-14** | Derive vendored/NuGet call sites (`src/Packages/<packagePrefix>.*`, `EF.*`) from the interface/source, XML docs, or a compiled reference call site, never naming conventions. Verify both member names and argument order; `DomainError.Create(string error, string code)` is message first. | Heuristics create plausible calls that fail compilation or silently swap argument meaning, then fan out across generated handlers. | [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; [support/ef-packages-reference.md](support/ef-packages-reference.md); [templates/cqrs-handler-template.md](templates/cqrs-handler-template.md); [templates/service-template.md](templates/service-template.md). |
| **GR-15** | Mutate aggregate-internal children (owned 1:N or aggregate-local M:N junctions) only through the root. Give them no standalone create/update/delete CQRS handler, service write, or endpoint. Use root `Add*`/`Remove*` methods, an updater that calls those methods rather than mutating collections, and nested root routes. Child reads are allowed; independent roots keep the full slice. | Standalone child writes bypass root invariants and duplicate child logic, breaking the aggregate's single consistency boundary. | [skills/domain-model.md](skills/domain-model.md), Aggregate Roots vs Internal Children; [support/vertical-slice-checklist.md](support/vertical-slice-checklist.md); [templates/endpoint-template.md](templates/endpoint-template.md); [templates/cqrs-handler-template.md](templates/cqrs-handler-template.md); `AggregateBoundaryTests` in [templates/test-templates-quality.md](templates/test-templates-quality.md); [templates/updater-template.md](templates/updater-template.md). |
| **GR-16** | Default `EntityBase.Id` to application-assigned `Guid.CreateVersion7()` and EF `ValueGeneratedNever()`. Store-generated keys require an explicit developer request recorded in `.scaffold/DESIGN-DECISIONS.md`. For a deviating root with children, updater `createFunc` and nested child handlers must call `db.Add(child)`. | Application-assigned keys are stable before save and let EF insert one graph; with store generation, EF can infer a navigation-added child as `Modified`, causing `DbUpdateConcurrencyException` unless explicitly added. | [skills/domain-model.md](skills/domain-model.md), Entity Base Class; [templates/ef-configuration-template.md](templates/ef-configuration-template.md); [templates/updater-template.md](templates/updater-template.md), New children and EF Added state. |
| **GR-17** | Only `{App}.DatabaseMigrator` owns schema. Runtime hosts never migrate, create, or patch schema at startup; they validate and fail fast. The migrator orders every migration-owning context, each with its own schema/history table. Locally, runtime hosts `WaitForCompletion(migrator)`. In Azure, a one-shot Container Apps Job runs before rollout, and only its identity has DDL rights. | Concurrent runtime DDL races deployments and broadens privilege; one ordered owner makes schema application deterministic and failure explicit. | [support/data-persistence-advanced.md](support/data-persistence-advanced.md), Migration Ownership; [patterns/infrastructure-wiring.md](patterns/infrastructure-wiring.md), Aspire Resource Wiring; [skills/cicd.md](skills/cicd.md), Production DB Migration; [skills/bootstrapper.md](skills/bootstrapper.md), Example Startup Tasks. |
| **GR-18** | Before using a first-party generated DTO/response, read its actual properties; before injecting into a generated class, read its constructor. Never infer shape from notes, sibling files, or naming. This extends GR-14 to generated app code. | Assumed properties cause `CS1061`; assumed constructor arity causes duplicate/mismatched parameters, repeated across every generated consumer. | [ai/SKILL.md](ai/SKILL.md), Non-Negotiables; [skills/ai-integration.md](skills/ai-integration.md), Non-Negotiables. |

## Adding or Changing a Rule

- Add only rules binding across every phase; stack-specific guidance belongs in its skill.
- Every row needs an enforcement location and a causal failure or decision boundary. Add enforcement before promoting an unenforced rule.
- Mark replacement as `superseded by GR-NN`; do not delete referenced IDs.
- Never renumber a referenced ID. Append new rules.
